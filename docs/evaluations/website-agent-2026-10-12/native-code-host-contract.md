## Environment and dynamic-tool contract

The schemas generated by this same installed binary are at:

- `/home/ubuntu/oak-login-20261011/acceptance-native-schema/v2/ThreadStartParams.json`
- `/home/ubuntu/oak-login-20261011/acceptance-native-schema/v2/TurnStartParams.json`

`thread/start.environments=[]` disables sticky environment access unless a
later turn explicitly overrides it. `turn/start.environments=[]` disables
environment access for that turn. `ThreadStartParams.dynamicTools` is a
separate array of client-provided `DynamicToolSpec` entries. Thus an empty
environment list does not itself remove the client tool schema or require the
JavaScript orchestration host to be disabled.

## Minimal harness correction

Set only `features.code_mode_host=true`, preserving
`features.code_mode=false`, `environments=[]` on both thread and turn start,
the two explicit client tools, existing MCP/builtin disables, and all client
tool authority checks. Do not enable shell, an executor environment, a remote
code-mode host, or additional native tools for this correction.

The host makes already-authorized tool callbacks executable; it does not
replace the client allowlist or broaden a callback's authority. A future
test must still verify actual callback execution and cleanup. This evidence
does not claim that a revised held-out test or a website workflow passed.
